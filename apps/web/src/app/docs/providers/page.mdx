# Providers

Slice 1.8 supports **17 hosted connection types** through one gateway-owned provider catalog. The web app reads that catalog from `GET /manage/provider-catalog`; provider identity is not maintained as a second frontend list.

## Connection lifecycle

1. Choose a provider from the gateway catalog.
2. Enter the credential and any provider-specific connection fields.
3. Test the credential and discover/normalize models.
4. Save only after validation succeeds.
5. Use any discovered model as a Route target.
6. Re-test later to refresh provider health and model metadata.
7. Disconnect after removing the provider from Routes that reference it.

Saved credentials are encrypted by the gateway and stored in the private Postgres credential path. The browser can read provider identity, health, connection-safe metadata, and discovered models, but never the decrypted key.

Model metadata is evidence-based. Missing pricing, context, maximum output, or capability data remains `unknown`; SwitchRoute does not invent a quality score.
